# Configuration and deployment

## Local setup

Follow root README. Run `python tools/setup_local.py` from the repository root. It creates an ignored, owner-only `.env` with the local merchant URL, generated RSA key, random session secret, initial shared demo password and blank FE URL. It is non-interactive and refuses to overwrite an existing file. Never commit the generated key or session secret.

## Demo users in the repository

`fixtures/demo_users.json` holds ten synthetic accounts: `demo`, `demo2` through `demo10`. All use the shared **`DEMO_USER_PASSWORD`** value from the deployment environment. Each account has a stable ID (`demo-user-001` through `demo-user-010`); the fixture contains no password or password hash. Both local and Vercel deployments read the same profiles, while their passwords can differ. Setup writes an initial example password `MuridWukongDemo123!` to the ignored `.env`; replace it with your chosen password.

User profiles remain in the repository; only the shared password is environment configuration. `DEMO_USERS_JSON` is no longer read. To add/change demo profiles, edit the fixture and redeploy; retain existing stable IDs when preserving ownership. The fixture is outside `public/` and has no HTTP asset route. Do not change the static-asset setup to expose it. It remains readable in this public repository by design.

## Required environment variables (four)

| Name | Purpose | Value source |
| --- | --- | --- |
| `MERCHANT_PUBLIC_URL` | Exact merchant browser origin for CSRF checks; default JWT issuer when not overridden. Not the FE or Go API URL. | `http://localhost:8000` locally, or the stable HTTPS Vercel domain without trailing slash. |
| `JWT_PRIVATE_KEY_PEM` | Private RSA signing key, at least 2048 bits; also derives public JWKS. Server-only secret. | Generated by setup helper; real newlines or literal `\\n` accepted. |
| `SESSION_SECRET` | Random signing secret for merchant login cookies. Server-only; keep consistent across instances. | Generated by setup helper. Changing it invalidates existing sessions. |

Login needs merchant URL, session secret and a non-empty `DEMO_USER_PASSWORD`. Passwords accepted by the login schema are 1–256 characters. Missing/empty password configuration returns 503; a wrong password or unknown username returns 401. Comparison uses constant-time byte comparison and the password never appears in an API response. Restart locally or redeploy on Vercel after changing it. Existing cookies/JWTs are not revoked by a password change. Token issuance and public JWKS additionally need the RSA key. `/api/health` remains a liveness endpoint and does not verify these settings.

The fourth required setting is:

| Name | Purpose | Value source |
| --- | --- | --- |
| `DEMO_USER_PASSWORD` | Shared password for all ten demo usernames; server-only. No built-in fallback. | Set your chosen password in `.env` / Vercel. Setup initially writes `MuridWukongDemo123!`. |

## Optional environment variables

| Name | Default | When to set |
| --- | --- | --- |
| `MINIAPP_FRONTEND_URL` | Empty | Set the FE entrypoint when available. Empty disables external launch; built-in receiver demo works. |
| `MINIAPP_API_BASE_URL` | Empty | Go API origin/tunnel for `tools/smoke_auth.py` only. Not used by the runtime as a frontend proxy. |
| `MERCHANT_CODE` | `murid_wukong_demo` | Override only if the registered merchant code differs. |
| `JWT_ISSUER` | Value of `MERCHANT_PUBLIC_URL` | Override for an explicitly registered issuer. Changing merchant URL otherwise also changes the issuer. |
| `JWT_AUDIENCE` | `bevia-miniapp` | Override if a different audience is agreed and registered. |
| `JWT_KEY_ID` | `murid-wukong-demo-v1` | Override to identify a different signing key, coordinating JWKS/rotation with the service. |
| `GOPAY_SIM_BASIC_CREDENTIAL` | None (unset) | Secret. Enables the GoPay-like auth-code exchange. It is the exact string callers send after `Authorization: Basic ` and is compared verbatim. Unset or empty makes `POST /v1/mini-apps/authorizations/token` answer 503; the JWT mode is unaffected. Setup generates a random value only for a freshly created `.env`; for Vercel set your own random value privately and share it only with the Mini App server that performs the exchange. It reuses `SESSION_SECRET` to sign codes and tokens, so that secret must also stay stable. |

Unset or empty optional identity overrides use their defaults. Existing non-empty overrides continue to work. Effective issuer, audience, merchant code and JWKS must match service registration, regardless of defaults. Keep the merchant URL stable after registration.

## Migrating an existing environment

Remove `DEMO_USERS_JSON` from local/Vercel configuration: profiles now come exclusively from the repository. Add `DEMO_USER_PASSWORD` explicitly; password hashes formerly stored in fixtures are no longer used. Remove `MERCHANT_CODE`, `JWT_ISSUER`, `JWT_AUDIENCE` and `JWT_KEY_ID` if they equal the documented defaults; preserve any intentionally different registered values. Keep the existing RSA key and session secret. Login now accepts only the shared deployment password. Existing sessions whose subject matches a fixture user ID can remain valid until expiry; changing passwords alone does not revoke stateless cookies or existing JWTs.

Do not rerun setup over an existing `.env`. Edit it deliberately; do not replace registered signing keys just to simplify configuration. The old `.local-demo-login.txt` is obsolete and not read by the app.

## Vercel

1. Import this component repository into Vercel. Select `main` as the production branch.
2. Use FastAPI framework detection, root directory `.`, entrypoint `app.py`, dependencies from `requirements.txt`. No database or persistent filesystem is required. [Official FastAPI deployment guide](https://vercel.com/docs/frameworks/backend/fastapi)
3. Configure environment variables privately in Vercel, including the four required values: stable merchant URL, signing key, session secret and shared demo password. `.env.example` contains placeholders only. Preview and production must use their own consistent URL/configuration.
4. Configure `MINIAPP_FRONTEND_URL` when the FE team provides it. Redeploy after environment changes.
5. Ensure the registered JWKS URL is publicly reachable without deployment protection or redirects. Coordinate the project's protection settings with its owner; never expose credentials to bypass protection.
6. Check `/api/health`, public JWKS, login, test receiver and external FE container. Register the merchant separately in the Mini App service.

The repository is deployment-ready source, not proof of a deployed Vercel application. No Vercel deployment is performed automatically.

## Local backend and tunnel

A deployed server cannot reach the laptop's `localhost`. Expose the local Mini App HTTP service through an operator-managed HTTPS tunnel, then configure that URL in the receiving BFF or smoke check. Keep admin routes and operational endpoints protected at the tunnel/reverse proxy. Do not disable service authentication to make a test pass.

The reverse direction also matters: the local Go service fetches the simulator's public JWKS URL. If running the merchant locally without Vercel, use a reachable merchant tunnel or configure the local service's development HTTP allowance deliberately. Do not substitute a laptop loopback URL for a reachable address inside Docker.

## Operating limits and rollback

This is a developer sandbox. No account lockout, distributed rate limiter, session revocation store or password reset is implemented. Before public exposure configure rate limiting at the edge and use non-production identities. No real funds should depend on this simulator. Hostile scripts on a trusted FE origin can request JWTs, so treat the configured FE origin as trusted code.

Changing configuration or redeploying the prior commit rolls back the simulator. Changing issuer, merchant code, or keys can break verification and ownership; coordinate with service administrators. Do not regenerate signing keys on startup. See backend guidelines for the unimplemented multi-key rotation requirement.
